# PrintLink Security / Threat Model

PrintLink is designed for small trusted office LANs (0.3 hardening applied).
This document states what it protects, what it does **not** protect against,
and the reasoning behind the storage layout.

## Data layout (since 0.3)

| Item | Location | Contains |
|---|---|---|
| `printlink.db` | `%PROGRAMDATA%\PrintLink` (shared) | **shared printers only** — no secrets |
| `identity.json` | `%PROGRAMDATA%\PrintLink` (shared) | this PC's public ID (`pc_id`) |
| `printlink-private.db` | `%LOCALAPPDATA%\PrintLink` (per-user) | grants / remote printers, **pairing tokens** |
| `target.json` | `%LOCALAPPDATA%\PrintLink` (per-user) | last selected remote printer |
| logs | `%PROGRAMDATA%\PrintLink` | job metadata, sender/host IDs |

If the shared dir is not writable (e.g. an ACL misconfiguration), the
shared side falls back to per-user `%LOCALAPPDATA%\PrintLink` — with the
consequence that each Windows account then sees only its own printer list.
The private side is always per-user.

## What a pairing token is

A token is generated by the **host** when it accepts a share request and is
stored in the host's private `grants` table and the sender's private
`remote_printers` table. It is key material for:

1. **Authorization** — requests carry `hmac_sha256(sha256(token), nonce)`
   over a single-use challenge (`/auth-challenge`, 120 s TTL). The token
   itself never crosses the network; replay dies with the nonce.
2. **Confidentiality** — job payloads are AES-256-GCM encrypted under a
   key derived from the token; tampering fails decryption (HTTP 401).

Pre-0.3 agents put the raw token in a plaintext `X-Token` header on every
request — that path survives only behind `LEGACY_TOKEN_AUTH=True` so mixed
fleets keep working during upgrades, and it is logged as a deprecation each
time. Flip the flag off once every PC runs 0.3+.

## Sender-side identity verification

Before any sensitive call (pairing, printing, revoking), the sender resolves
the host ID to an IP via mDNS (or the stored last-IP fallback) and then
**verifies via `/ping` that the machine at that address really advertises
that ID**. Verified routes are cached for 60 s. A stale IP after DHCP churn,
or an mDNS spoof, fails closed instead of leaking credentials or documents
to the wrong machine.

## Threats on a shared PC (local user B vs. user A's data)

The pre-0.3 world made every token world-readable/writable in
`%PROGRAMDATA%`. Since 0.3:

- **T1 — Token theft across accounts (read): mitigated.** B can no longer
  read A's grant/token rows; they live in A's private profile. B *can*
  still read anything running as A themselves (same-user processes are
  always in scope).
- **T2 — Grant injection into another account's host (write): mitigated.**
  Host grants live per-account; B cannot mint access into A's host db.
- **T3 — Tampering with shared state: partially open by design.** The
  machine-wide shared dir holds only the printer list; B can rename/disable
  shared printers or delete the shared db (nuisance/denial of service), but
  cannot touch tokens. BitLocker + admin-managed accounts shrink this
  further.
- **T4 — LAN capture:** payloads remain AES-GCM-encrypted and the credential
  is no longer observable on the wire at all. A passive observer gets HTTP
  metadata (IPs, sizes, timing) and nothing usable. An active MITM can
  still deny service or tamper with connections (no TLS yet — see below).

## Why the split stops there

Agents run per-user at login, and the shared printer list must be identical
for every account (the right-click verb works from any desktop). That list
contains no secrets, so keeping it machine-writable costs only nuisance-level
tampering. Restricting it to Admins would push non-admin machines back onto
per-user printer lists and resurrect the "shared printer missing" bug.

## Remaining gaps / next hardening steps

- **No TLS**: metadata is visible on the LAN and active MITMs can disrupt
  (not read) jobs. Candidate: self-signed cert pinned per pairing.
- **Legacy X-Token auth** remains available for old peers until
  `LEGACY_TOKEN_AUTH` is switched off fleet-wide.
- **Untrusted file processing**: the host renders attacker-influenced files
  with PyMuPDF/GDI+/Word. Keep hosts patched; treat a hostile document as
  in-scope for those parsers (true of any print pipeline).

## Report a vulnerability

Open an issue on https://github.com/najm07/Printlink/issues and mention
"security" — this is a hobby LAN tool; fix priority is low unless the
exposure is remote.
