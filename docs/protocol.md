# PrintLink Protocol Specification

Wire contracts between PrintLink agents.
All multi-byte integers little-endian. All timestamps UTC `YYYY-MM-DD HH:MM:SS`.

## 1. mDNS advertisement

- Service type: `_printlink._tcp.local.`
- Instance name: `printlink-<ID>._printlink._tcp.local.` (ID = 9 digits, no spaces)
- Port: 9100
- TXT properties: `id=<9-digit ID>`

Clients resolve `ID -> (ip, port)` from browse results; the ID is re-verified
against `/ping` before any trust is placed in an IP.

## 2. HTTP API (host agent, TCP 9100)

### GET /ping
Response `200`:
```json
{ "id": "482 917 305", "ok": true, "version": "0.3.0" }
```
Senders verify this ID against the one they dialed BEFORE sending anything
sensitive; verified routes are cached briefly (60 s).

### GET /auth-challenge?sender_id=<id>
Single-use HMAC challenge (see §4). Response `200`:
```json
{ "nonce": "<urlsafe, ~24 chars>" }
```
Nonces expire after 120 s and are consumed on first use. `400` on a
malformed sender_id. Absent endpoint ⇒ pre-0.3 host; senders fall back to
legacy `X-Token` auth until the fleet is updated.

### GET /printers
Response `200`:
```json
[{ "alias": "Accounting-HP",
   "status": { "offline": false, "paused": false, "error": false,
               "jobs_queued": 0, "port": "USB001" } }]
```

### POST /request-share
Request:
```json
{ "sender_id": "111 222 333", "sender_name": "Ahmed-PC",
  "printer_alias": "Accounting-HP", "days": 7 }
```
The host shows an accept/refuse dialog to the local user (auto-declines
after 60 s). Requests are rate-limited per client IP (5 per 15 min).
`days` is clamped server-side into `[1, MAX_SHARE_DAYS=90]` regardless of
what the client sends.

Responses:
- `200` accepted:
```json
{ "status": "accepted", "token": "<64 hex chars>",
  "expires_at": "2026-08-09 13:44:00" }
```
- `400` malformed field: `{ "status": "refused", "reason": "invalid days" }`
- `403` refused: `{ "status": "refused", "reason": "user declined" }`
- `404` printer not shared: `{ "status": "refused", "reason": "printer not shared" }`
- `429` rate-limited: `{ "status": "refused", "reason": "too many requests" }`

The token is stored on both sides. Re-requesting renews the grant and rotates
the token (upsert on `(remote_id, printer_id)`).

### POST /print
Headers:
- `X-Sender-ID: 111 222 333` (any spacing; normalized server-side)

Auth headers — 0.3 HMAC flow (preferred; token never transmitted):
- `X-Token-Hint: <sha256(token)[:16]>`   (grant lookup aid, not secret)
- `X-Nonce: <value from /auth-challenge>` (single-use, 120 s TTL)
- `X-Signature: hex(hmac_sha256(sha256(token), nonce))`

Legacy (pre-0.3 peers, accepted while `LEGACY_TOKEN_AUTH` is on):
- `X-Token: <64 hex chars>`

Body (two layers, inner first):
1. File bytes encrypted with AES-256-GCM, key = SHA-256(token bytes from hex),
   nonce prepended: `[12B nonce][ciphertext+16B tag]`
2. Sent as `multipart/form-data`, field name `file`, filename preserved
   (extension carries format: `.pdf`, `.png`, `.xps`)

Max body: 100 MB.

Responses:
- `200`: `{ "status": "accepted", "printer": "Accounting-HP" }`
- `400`: `{ "error": "no file" | "invalid payload" | "invalid options" }`
- `401`: `{ "error": "decrypt failed" }` (wrong token / tampered payload)
- `403`: `{ "error": "unknown ID or proof" | "invalid or expired challenge"
           | "unknown ID or token" | "share was revoked" | "share expired" }`
- `500`: `{ "error": "print failed" }` (details only in the host's log)
- `503`: `{ "error": "printer is offline" }`

The host checks, in order: credentials valid (HMAC proof over a fresh
nonce, or legacy token) -> not revoked -> not expired (marks `expired`
on first overdue use) -> printer still shared and enabled -> printer
not offline -> decrypt -> spool -> reply. The reply is sent only after the job
finishes printing locally, hence the 180s client read timeout.

## 3. Legacy named-pipe framing — removed

The port monitor and its pipe (`\\.\pipe\PrintLinkSender`) were retired in
0.2.0 when PrintLink moved to direct send; the pipe reader itself was deleted
in 0.3.0. See git history or `docs/debugging-notes.md` for how it worked.

## 4. Pairing token

- 32 random bytes, hex-encoded (64 chars), generated by the host on accept.
- Serves as: AES-GCM key source, HMAC auth key (0.3+), grant identifier.
  It is NOT sent over the wire anymore — requests carry a per-nonce HMAC
  proof plus a non-secret `sha256(token)[:16]` lookup hint instead.
- Rotation: every re-request issues a new token and resets the expiry window.
- Revocation/expiry is enforced host-side; a leaked token dies with its grant.

## 5. POST /revoke-grant body

0.3 flow:
```json
{ "sender_id": "111 222 333", "printer_alias": "Accounting-HP",
  "nonce": "<from /auth-challenge>", "signature": "<hmac>" }
```
Legacy fallback: same body with `"token": "<64 hex chars>"` instead of the
nonce/signature pair. Responses: `200 {"status":"revoked"}` or
`404 {"status":"refused","reason": "..."}`.

## 6. Error codes summary

| Layer | Condition | Signal |
|---|---|---|
| mDNS | host not found | sender: "Host not found on the LAN" |
| /ping | ID mismatch | sender: "ID mismatch: ..." |
| request-share | declined | 403 + reason |
| request-share | flood | 429 "too many requests" |
| print | bad token (legacy) | 403 "unknown ID or token" |
| print | bad/expired nonce or proof | 403 "invalid or expired challenge" / "unknown ID or proof" |
| print | expired | 403 "share expired" (state flips to expired) |
| print | revoked | 403 "share was revoked" |
| print | printer offline | 503 |
| print | decrypt fail | 401 (InvalidTag) — treated as tamper |
| print | local spool error | 500 "print failed" (detail in host log) |
